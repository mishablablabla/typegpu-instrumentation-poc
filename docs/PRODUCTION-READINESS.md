# Production readiness

Date: 2026-10-27, revised 2026-10-28 (second independent audit, evidence re-checked against the raw artifacts, ecosystem research added: see [ECOSYSTEM-RESEARCH.md](ECOSYSTEM-RESEARCH.md)). Scope: the opt-in instrumentation layer for TypeGPU (`typegpu/unstable-instrumentation` + the hook patch in 12 core files), as a **developer diagnostics tool**. Evidence labels: **[run]** = a command in this repo produced it (raw data under `real-gpu/results/`, `package-test/results/`, `mutation/`); **[derived]** = follows from reading code, not run; **[not done]** = no evidence exists.

## Verdict: conditionally ready as an experimental, opt-in developer tool (one verdict per scope below)

Usable as an **opt-in development and diagnostics feature**, within the constraints below. It is **not** claimed ready as an always-on production default, and **not** claimed ready for any environment not listed in the support matrix.

Why not *PRODUCTION-READY*: one mandatory row is only partly evidenced (C1, browser/GPU breadth), two **provisional** budgets are missed by the measurements (B1 residual, P3 per-event cost), and demand is unvalidated (the research found no signal either way, see below). Why not *NOT READY*: no correctness or memory defect is known that makes the supported scope unsafe; the defects that two independent audits and mutation testing found were fixed with regression tests; the open deviations that remain are listed in [EVENT-CONTRACT.md](EVENT-CONTRACT.md#known-deviations-found-by-audit) and below, none of them lets an internal error reach the application; the disabled path costs nothing measurable at run time and no hub bytes in a bundle.

No single label covers these; each scope has its own.

| **Cross-platform compatibility** | **Partially established** | Chrome and Safari on an Apple M3 Pro Mac (hardware), plus GitHub-hosted runners on **software or virtualised adapters only**: Chrome on Linux, Windows (WARP/D3D12) and macOS, Edge on Windows, Firefox on Linux; the mock tests on Linux, Windows and macOS. **Concrete blockers to PRODUCTION-READY** (each says what evidence would close it):

1. **Breadth.** Hardware validation is one Mac (Apple M3 Pro): Chrome 156 (headless and headed) and Safari 26.3. Other platforms are covered only on software/virtualised adapters (GitHub-hosted runners, see the CI matrix below). No physical GPU on Windows or Linux, no discrete GPU, no Firefox or Safari on a real GPU, no real device reset. *Close with:* `node real-gpu/run.mjs --call 'window.runViability()'` on those machines (the harness records the environment), or a self-hosted runner with a GPU.
2. **Bundle residual for non-users is 0.7–0.8 KB gzip (≈ 1 %), above the provisional 0.5 KB target.** The hub itself costs non-users zero bytes. *Close with:* either accept the residual as the price of the hooks, or move payload construction into the hub (estimated −100…150 B gzip).
3. **Per-event cost is 0.4–0.6 µs per tracked object plus 0.2–0.4 µs per event** (provisional budget "≤ 1 % of the emitting operation" is violated for cheap operations such as buffer or bind-group creation). Fine for a dev tool, unsuitable as an always-on default. *Close with:* a maintainers' decision on the intended use, or a sampling mode.
4. **The core patch is not upstream.** It applied to upstream `main` when checked (at `156b99d`: patch applies, 118 instrumentation tests passed then, `tsc` clean [run]; on 2026-10-27 the `upstream-drift` job was green on GitHub Actions) but nothing guarantees it keeps applying, and the job proves **only** that the hunks apply, the overlay compiles against upstream's types and the instrumentation tests pass on a mock device. It does not prove that hook placement is still semantically right after an upstream refactor, runs no upstream tests and no real WebGPU, and (being a scheduled workflow) is disabled by GitHub after 60 days without repository activity.
5. **Blind spots are real and listed**: helper submissions, wrapped GPU objects, restored pipelines, samplers, texture views, render bundles, raw WebGPU calls. A device-level tap would cover most of them (prototype in `experiments/device-tap`), at a cost that rules it out as the primary mechanism ([ARCHITECTURE-DECISION.md](ARCHITECTURE-DECISION.md)).
6. **Demand is unvalidated; overlap is now characterised.** The Runtime Inspector MCP was read from its public source: an offline, one-shot validator that stubs submits and pipeline initialisation in its own headless Chromium, so it is a complement or a possible consumer, not a duplicate; WebGPU Inspector is the real competitor for raw WebGPU. At the *information* level nothing in the three scenarios is unique (Chrome already prints the compiler message, the thrown `ResolutionError` already names the slot), so the case rests on attribution and on TypeGPU facts only TypeGPU can emit. Zero upstream issues or discussions on devtools or instrumentation were found, and upstream issue #2935 (source maps, device-error RFC item) may make `shader-diagnostics`/`device-error` partly redundant. *Close with:* the three steps in [ECOSYSTEM-RESEARCH.md](ECOSYSTEM-RESEARCH.md#recommendation).
7. **Open deviations** (EVENT-CONTRACT.md §Known deviations): `phase: 'resolve'` covers more than WGSL generation; a retry loop on a broken pipeline emits one failure per frame and evicts the explaining events from the ring; `device-lost` is not recorded while the layer is disabled; render-bundle draws are counted at record time; retained memory can reach about twice `historyMaxBytes`. *Close with:* design decisions (coalescing rule, recording loss while disabled), not more tests.

## Mutation testing, final layer

Round 2 (156 mutants of option validation, delivery, history/byte accounting, pinned failures, sweep, pipeline events and ids, terminal teardown, late loss, size estimate, hook order and `try/catch` placement in the patch, consumers) was **re-run from scratch on 2026-10-28** against the layer and the 211 tests of 2026-10-27: **149 killed (95.5 %)**, 7 survivors [run: `mutation/results_round2_e3dda55.json`]. The committed round-2 files before that re-run gave only 146 (re-run files of four mutants were not committed), which is why this was repeated. The 7 survivors: unsubscribe leaves an inactive entry in an array (memory only), `dispose` keeps its surfaced-error memory (memory only), history arrays never compacted (heap only; the API-visible effect is covered), compaction threshold (equivalent), several `device-lost` events retained (a device is lost once), sweep threshold does not double (about 5× slower, not wrong), and one undocumented size constant.

After the second audit's fixes the same 156 were run on the new layer with 219 tests [run: `mutation/results_round2_postfix.json`]: three mutants target code that moved and were re-expressed, two became equivalent because of the new guards, one kill was GC-dependent and was made deterministic. **Current: 147 of 156 killed (94.2 %)**; round 3 on the code the fixes added: **14 of 14** (after two weak assertions were strengthened); combined **161 of 170 (94.7 %)** [run: `mutation/results_round3.json`; details in [mutation/README.md](../mutation/README.md)]. All earlier known bugs (hub retaining the root, per-hub device listener) are killed by the GC tests. A mutation score says the tests notice one-line changes in these files, not that the design is right.

## Architectural decisions and alternatives rejected

[ARCHITECTURE-DECISION.md](ARCHITECTURE-DECISION.md) has the full comparison. In one line each: kept the root-scoped hub with a device-scoped weak listener registry; **adopted** a separate entry point (0 hub bytes for non-users); **rejected** loading the hub with dynamic `import()` (root construction is synchronous: early events would be lost); **rejected** device-level interception as a replacement (it cannot see TypeGPU semantics and costs ≈ 4 µs per encoder) and **recommended it as a complement**; **not built**: activation through a global hook for tools.

## Remaining limitations and unresolved risks

- The seven blockers above.
- `disable()` is a blind spot, not a pause: objects created meanwhile stay untracked, and a device loss during that time is never recorded or announced after `enable()` (audit D-4; pinned by test M22); documented.
- `phase: 'resolve'` is "anything thrown before the pipeline-creation call", not only WGSL generation, and then carries `wgsl: null` although the code existed (audit D-2); documented. The better fix lives in the patched pipeline files.
- A render loop that retries a broken pipeline every frame emits one `pipeline-creation-failed` per frame (audit D-3): the 256-event ring turns over in about 4 s at 60 fps and evicts the events that explain it; `retainedFailures` keeps 16. No coalescing rule exists yet.
- Draws recorded into render-bundle encoders are counted when recorded (audit D-8); retained memory can reach about twice `historyMaxBytes` plus live-pipeline WGSL (audit D-12); the hub may keep the `GPUDevice` wrapper reachable while a consumer holds the facade after `dispose()` (audit D-11, suspected, not measured).
- `origin: 'adopted'` can also appear for a bind group another root created and a snapshot cached; `bind-group-created.label` is the layout's name while `snapshot.bindGroups[].label` is the group's own (null): both documented in the contract, unchanged.
- Several roots on one device each report the same `device-error`; a `device-error` cannot be attributed to a pipeline from the browser's message alone (labels are not unique: identical WGSL returns the first module and its label).
- The registry's memory is bounded by V8's collection cadence (an uncollected object keeps its record): in a no-GC-pressure loop it plateaus at tens of MiB (measured 35–42 MiB at 200 k+ dropped buffers) — comparable to the objects it tracks, bounded, but not small.
- Performance numbers: one machine, one browser, synthetic workloads, 60 s sustained runs; whole-operation overhead is derived, not directly measurable below ±1.4 %. Safari timing was not measured. Not measured at all: real console/file/network reporter I/O, render-pipeline creation, asynchronous compile-diagnostic cost, `submitted()` in isolation. The raw benchmark rows carry no source hash, so which hub produced a result is inferred from timestamps ([PERFORMANCE.md](PERFORMANCE.md) §Provenance).
- Not exercised on any real device: GPU reset (`device-lost` with a reason other than `destroyed` is simulated only), memory-pressure loss, multi-GPU systems.
- CI workflows (`checks`, `upstream-drift`, `packaging`) ran on GitHub Actions (ubuntu-latest, Node 24) on 2026-10-27, run 40596740393: all three green. The first two runs of `packaging` failed because the bundle matrix needs bundlers that the filtered upstream install does not provide (webpack, rollup plugin, terser); the install step was added. The real-GPU suites stay manual by design (hosted runners have no GPU). ## What this document does not claim

No GPU execution time or GPU-side behaviour; no universal WebGPU coverage; no "memory-safe", "zero overhead" or "fully supported" in any unqualified sense — the scoped statements above are what the evidence supports: zero **hub bytes** in non-opting bundles (four bundlers), **no measurable** run-time difference for the disabled path on four operations (A/A-controlled, one machine), history **bounded by an estimated payload size**, registry **bounded by V8's collection cadence**.
