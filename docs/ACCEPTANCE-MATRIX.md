# Acceptance matrix

Written **before** the production-readiness work, from the viability gate's measured baselines ([VIABILITY-REPORT.md](VIABILITY-REPORT.md)). Every row says how it is tested and what passes. A threshold is **derived** (from a measured baseline or a stated use case) or **provisional** (a reasoned starting point plus the experiment that will settle it). Nothing here is declared satisfied until the "Evidence" column, filled in at the end in [PRODUCTION-READINESS.md](PRODUCTION-READINESS.md), points at a run.

Baselines this matrix is derived from (all measured, Apple M3 Pro / Chrome 156, see the viability report):
- whole dispatch (encoder + pass + submit) ≈ 2.5 µs CPU; an open-pass dispatch call ≈ 42 ns; `buffer.write` ≈ 190 ns
- A/A control (identical copy of the same code) differs from its twin by 0–3 % (0–6 ns); process-to-process spread of one configuration is 5–16 %
- hub code costs +3.1 KB gzip for everyone (statically imported)
- a 60 fps frame is 16.6 ms; a heavy WebGPU frame issues a few hundred to a few thousand dispatch/draw calls

| ID | Dimension | Requirement | How tested | Passes when | Threshold status |
|---|---|---|---|---|---|
| F1 | Functional correctness | Every operation hooked by the layer produces exactly the events its contract specifies, on a real GPU | `real-gpu` viability suite, every scenario, each supported environment | all checks pass; counts equal the calls made; three views (subscription, console reporter, JSONL) agree | derived (exact) |
| F2 | Event semantics & ordering | Each event type has one documented meaning (attempted / created / failed / destroyed; sync / async); ordering promises are exactly what is tested | conformance tests per event on mock **and** real device; re-entrancy and async ordering tests | contract in `docs/EVENT-CONTRACT.md` ≙ tests, no promise without a test | derived (exact) |
| F3 | Diagnostic completeness | What the layer does *not* see is declared; nothing claims universal coverage | support-matrix table; "unsupported ops emit nothing and are listed in `snapshot.unavailable`" test; scenario list with expected reporter output | every unsupported item is listed, each tested not to produce a false event | derived (exact) |
| F4 | Diagnostic value | A realistic failure is explained by the output faster than with raw WebGPU/console | scenario scripts (broken shader, leak, per-frame pipeline recreation, hot reload) with expected reporter + JSONL text, run on real GPU | each scenario's reporter output contains the discriminating fact (e.g. generated-WGSL line of the error, the owning pipeline/label, the leaked resource) | qualitative, listed |
| P1 | Disabled-path CPU | Root created without instrumentation pays no meaningful runtime cost | browser A/A-controlled benchmark (`pristine`, `pristine-b`, `disabled`), fresh process per run, bootstrap CI over processes | CI of (disabled/pristine − 1) inside the A/A band on every operation **and** ≤ 3 ns per hooked call on the lightest op (open-pass dispatch, 42 ns) | provisional: 3 ns ≈ 1 branch + property load; revisit with CI width |
| P2 | Enabled-path CPU (hot paths) | Counters on dispatch/draw/write cost far less than the operation | same benchmark, `enabled` configs | ≤ 15 ns per call on dispatch/draw/write; ≤ 1 % of a full encoder+submit dispatch; **zero allocation** per hot call | provisional: 15 ns × 1000 calls/frame = 15 µs = 0.09 % of 16.6 ms |
| P3 | Event path CPU (cold paths) | Payload build, ring insert, subscriber fan-out, serialisation and console output are individually measured | Node microbench (mock device) + browser pipeline-creation/resource-churn runs | each cost reported separately with CI; event cost ≤ 1 % of the operation that emits it (pipeline creation ≥ 100 µs; buffer create ≥ 1 µs) | provisional |
| P4 | Sustained operation | Long run with steady event generation does not grow memory or slow down | 60 s browser run, heap trend, ops/s trend | heap slope within noise after warm-up; ring at its bound | provisional (duration), derived (criterion) |
| B1 | Bundle cost for non-users | Applications that never opt in do not ship the hub | real consumer bundles with Vite/Rollup, esbuild, webpack (minified, gzip, brotli), pristine vs patched vs patched+import | **0 bytes of hub code**; remaining hook-site cost quantified and ≤ 0.5 KB gzip | target 0; residual provisional |
| B2 | Import cost for users | Opting in costs what it costs, reported | same bundler matrix with the entry imported | reported (no pass/fail) | – |
| M1 | Retention after explicit cleanup | `root.destroy()` / `instrumentation.dispose()` leave no strong path to root, device listeners or hub | deterministic tests (listener counts, ring cleared, holder cleared) — **no GC needed** | exact counts | derived (exact) |
| M2 | Retention after abandonment | Roots dropped without `destroy()` (hot reload) are collectable | GC experiments, several rounds, mock **and** real device; flakiness reported | ≥ 95 % of abandoned hubs/roots collected in ≤ 5 GC rounds, 0 live listeners growth; not used as the only proof | derived |
| M3 | History memory | History bounded in bytes, not only entries | tests with large WGSL (≥ 500 KB) × many events, `historyMaxBytes` option; measured retained size | retained payload ≤ configured bytes + one event; overflow accounted (`droppedEvents`, `droppedBytes`) | derived |
| M4 | Subscriber lifetime | Unsubscribed/leaked subscribers behave as documented | tests: unsubscribe in listener, dispose, many enable/disable cycles | exact | derived |
| E1 | Failure isolation | A subscriber/reporter/serialiser failure never breaks the instrumented app or other subscribers; failures are observable, not silent; no unbounded recursion | tests: throwing, re-entrant, unsubscribing listeners; failure counter + `reportError`-style surfacing, rate-limited | app result unchanged; every failure visible in counters and surfaced once per distinct failure up to a limit | derived (policy) |
| E2 | Application errors | Instrumentation never swallows or alters an application error (e.g. rejected `initAsync`) | tests with instrumentation on/off compare rejection identity and message; real device | identical | derived (exact) |
| A1 | Public API | Types, naming, activation, lifecycle are documented and tested as a consumer would use them | consumer app compiled with `tsc` against the **built package** declarations; misuse tests (double dispose, enable after dispose, subscribe non-function, bad options) | compiles, documented misuse is defined behaviour | derived |
| A2 | Version/compat | Schema versioned, compatibility policy written, JSONL reader tests | tests | policy + version tests | derived |
| K1 | Packaging | Feature works from the **built** package through `exports`, ESM, declarations, `sideEffects` | pack/build typegpu, install into a throw-away consumer app, bundle it, run in Chrome | consumer runs, types resolve, hub absent unless imported | derived |
| K2 | Upstream drift | Hook patch applies to current upstream `main` | CI drift job | applies, tests pass | derived |
| C1 | Environments | At least two meaningfully different implementations are validated and recorded | Chrome/Dawn on Apple GPU (done), Safari/WebKit on Apple GPU, software adapter if obtainable; full environment record per run | each environment: counts, failures, skips, unsupported capabilities, headless/headed | derived; missing ones reported, never invented |
| T1 | Reproducibility | A third party can reproduce every number | from-scratch clone → single command per result; raw data committed | documented commands work on a clean copy | derived |
| T2 | Test quality | Tests do not merely restate the implementation | mutation testing (≥ 40 mutants), regression tests demonstrated to fail on the reintroduced bug | surviving non-equivalent mutants = 0 in hub/deviceEvents/hooks | derived |
| D1 | Documentation | Install, activate, use, troubleshoot; architecture and lifecycle; limitations | docs reviewed against real runs (commands copy-pasted from docs) | each documented command run verbatim | derived |

Noise vocabulary used in the performance report: **above noise** = the bootstrap CI of the effect excludes zero *and* the A/A band; **uncertain** = the CI includes zero or overlaps the A/A band; **measurable but insignificant** = above noise but below the budget; **violates budget** = above the budget in the table.

Not asserted anywhere: GPU execution time (no timestamp queries are used), universal WebGPU coverage, behaviour on drivers/browsers not listed in the environment record.
