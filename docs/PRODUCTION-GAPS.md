# Remaining production-readiness gaps

> **Historical.** Written at the end of the usable-output milestone. Gap 4 (CI) and 5 (bundle) and parts of 2, 7, 8 have been addressed since; the current state of every requirement is in [PRODUCTION-READINESS.md](PRODUCTION-READINESS.md).

Ranked by how much each one blocks a production release. Evidence is from this repo's own runs; **[measured]** = a command was run and its result is quoted, **[derived]** = follows from reading the code, **[not done]** = no check exists yet.

## Audit: what exists today (verified against the code and runs)

- **Events (9 types, `overlay/src/types.ts`):** `resource-materialized` (buffer, texture), `resource-destroyed`, `bind-group-created`, `pipeline-compiled`, `pipeline-compile-failed`, `shader-diagnostics`, `device-error`, `device-lost`, `root-destroyed`. Plus `getSnapshot()` (live resources, bind groups, pipelines with dispatch/draw counters, `submits`, and the `unavailable` list). No GPU execution time anywhere; CPU `resolveMs`/`createMs` are labelled as such.
- **How consumers receive them:** `root['~unstable'].instrumentation.subscribe(listener)` (synchronous, in `seq` order), `history()` (bounded ring), `getSnapshot()`. Opt-in at root creation with `unstable_instrumentation`.
- **Mock vs real GPU:** all 9 event types are covered by mock tests (51 tests). On the real device (Apple M3 Pro, Chrome 156) these are validated: materialize (buffer, texture), destroy, bind group, lazy `pipeline-compiled`, `pipeline-compile-failed` (compute, async), `shader-diagnostics` (valid and invalid), `device-error`, `device-lost` (`destroyed`, owned and borrowed), `root-destroyed`, buffer write counters, GC. **Not validated on a real device:** `pipeline-compile-failed` for render pipelines, explicit `initSync`/`initAsync` *success* triggers, texture destroy, `device-lost` with a reason other than `destroyed`.
- **What a user had to do before this slice:** run the unit tests, or `real-gpu/run.mjs`, whose output is pass/fail checks (the first 80 events only land in a JSON result file). There was no way to run an existing scenario and look at its events. Now: `node real-gpu/run.mjs --example <file> [--jsonl <out>]` (README).
- **Patched internals:** the core is a module in `core/instrumentation/` plus a hook patch in 10 TypeGPU files (+210/−37). If the hooks are absent: [measured] an unpatched TypeGPU accepts `unstable_instrumentation` and silently ignores it; `root['~unstable'].instrumentation` is `undefined` and the scenario runs with no data. The harness now turns that into an explicit error (`requireInstrumentation`, tested).

**Update after the viability gate** ([VIABILITY-REPORT.md](VIABILITY-REPORT.md)): render-pipeline async failures, texture destroy, explicit `initSync`/`initAsync` success and sync failures are now validated on a real device; browser overhead and bundle size are measured (hub: +3.1 KB gzip for everyone); a device-listener retention defect was found and fixed (row 5 below mentions the remaining bundle cost).

## Gaps, ranked

| # | Gap | Severity | Evidence | What would close it |
|---|---|---|---|---|
| 1 | **Depends on an unmerged patch of TypeGPU internals** | Blocks any use outside this repo | The hooks are in `init.ts`, `buffer.ts`, `texture.ts`, both pipeline files, `drawState.ts`, both pass files, `commandEncoder.ts`, `rootTypes.ts`. [measured] The patch applies cleanly to upstream `main` 25 commits after the pinned base (`156b99dc`), and there the 51 new tests and the 2987 existing tests pass and `tsc` is clean: drift tolerance is decent so far. There is no automated drift check, and nothing says upstream will accept the hooks. | Propose the hooks upstream (the funnels are few); until then a scheduled job that applies the patch to upstream `main` |
| 2 | **Collection has silent blind spots** | High | [derived] Not seen: wrapped `GPUBuffer`/`GPUTexture`, helper submissions (`buffer.clear/copyFrom/read`, texture/mipmap utilities, query sets), `encoder.finish()` paths, raw WebGPU calls, samplers, vertex layouts, render bundles, texture writes, precompiled/restored pipelines. `submits` counts `TgpuCommandEncoder.submit()` only. Several roots on one device each report the same device error. These are listed in `snapshot.unavailable` but not per-event. | Decide per blind spot: hook it or document it; add a per-snapshot completeness indicator (e.g. count of raw-accessed passes) |
| 3 | **Tested on one browser and one GPU** | High | [measured] Chrome 156, Apple M3 Pro, headless. [not done] Safari, Firefox, Windows/Linux, discrete GPUs, headed mode, a genuine device reset. | Run `real-gpu/run.mjs --chrome <path>` on other machines; record each |
| 4 | **No CI, and hosted runners have no GPU** | High for reproducibility | There is no `.github/workflows`. [derived] GitHub-hosted runners have no GPU, so the real-device run cannot be a hosted job: only mock tests, `tsc`, lint and the patch-drift check can. Upstream recently added GPU test infrastructure (`#3263`, Dawn-based) that could be reused on a self-hosted or software runner. Setup from scratch is reproducible: [measured] `scripts/setup.sh` + tests in a fresh copy, ~10 s of install. | Hosted workflow: setup, `scripts/test.sh`, type check, lint, drift check against upstream `main`. Keep real-GPU runs a manual, recorded step |
| 5 | **History is bounded by count, not bytes; hub code ships to everyone** | Medium | [derived] The ring holds up to 256 events (configurable) and `pipeline-compiled` carries the whole WGSL, so a few large shaders can hold megabytes. The hub is imported statically by `init.ts`, so every bundle containing TypeGPU's root includes it even when instrumentation is never enabled; the size is **[not done]**. The registry is weak and GC-verified on mock and real (REAL-DEVICE-VALIDATION). | Cap by bytes as well as count; measure bundle size; consider loading the hub lazily or gating by a build-time constant |
| 6 | **Disabled-mode overhead: measured only on a Node mock** | Medium | [measured] Final run: disabled vs pristine +1.5 / −6.6 / +1.4 / +2.0 % against an A/A spread of 7–29 % (`bench/results/20261027-160102.jsonl`). [not done] In a browser with real WebGPU calls; bundle size. | Same three-way benchmark in Chromium against a real device |
| 7 | **Event ordering and error handling are sync and unspecified in places** | Medium | [derived] Listeners run synchronously inside the hook and must not call back into TypeGPU (undefined re-entrancy); exceptions are swallowed and counted. [measured] On a real device `device-error` for a bad shader arrives *before* its `shader-diagnostics`, and diagnostics settle after later events; consumers must not assume causal order across async events. | Specify ordering guarantees; consider microtask delivery |
| 8 | **API stability and version compatibility** | Medium, expected for a PoC | Everything is `~unstable`; event types are exported only by relative path, not through a public entry. [measured] Browser API drift already bit once (`isFallbackAdapter` moved to `adapter.info`). Event schema `v: 1` and JSONL `version: 1` exist but have no compatibility policy. | Public type export, compatibility policy, versioned JSONL reader tests |
| 9 | No exit-code policy for "diagnostics found" | Low | `run.mjs --example` exits 0 when the scenario finishes even if it produced device errors or compile failures (`examples/broken-shader.ts` exits 0). | A `--fail-on` option, if a gate is wanted |

Also worth knowing: the repository is public, so the commit history exposes the author's work e-mail; that is a repository-settings/identity decision, not something this work changes.
