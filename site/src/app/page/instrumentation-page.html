Instrumentation

Instrumentation reports what TypeGPU does on your behalf: the buffers and textures it creates, bind groups, pipeline compilation with the generated WGSL, shader compiler messages, device errors and teardown. You get them as plain-data events and as a snapshot of what is alive.

It is opt-in per root and has no UI. Print the events, assert on them in a test, or write them to a file. It does not report GPU execution time or raw WebGPU calls.

This needs a TypeGPU build that contains the hook patch from this repository; it is not in the published package. The API is unstable_ and can change.

Setup#

Then install the tarball in your app:

The instrumentation lives in its own entry point, typegpu/unstable-instrumentation. An application that does not import it contains none of its code.

Quick start#

Pass createInstrumentation() as unstable_instrumentation to tgpu.init or tgpu.initFromDevice, then read it from the root.

root['~unstable'].instrumentation is undefined when the option was not passed. A TypeGPU build without the patch ignores the option, so the check also catches a wrong build.

How it works#

Hooks inside TypeGPU's core report what happened. A hub keeps a bounded history and a snapshot. Everything above the event contract is a consumer, so the core has no UI, DOM or framework code.

Options#

OptionDefaultMeaning
historySize256Events kept for subscribers that attach late. 0 keeps none.
historyMaxBytes4 MiBCap on the estimated size of the kept history, in bytes. The newest event is always kept.
captureSourcetrueKeep the generated WGSL in pipeline events and snapshots. false keeps only its length (wgsl: null).

An invalid value throws from createInstrumentation(), before a device is requested.

Reading events#

Every event has v (schema version, currently 2), seq (1, 2, 3, … per root) and t (performance.now() at emission). Listeners run synchronously, in seq order.

Event types

typeEmitted whenUseful fields
resource-materializedA buffer or texture gets its GPU object.resource, id, label, sizeBytes (buffer), format and size (texture)
resource-destroyedA tracked buffer or texture is destroyed.resource, id, label
bind-group-createdA bind group is created, or wraps one you created.origin, entries[].resourceId (null: not tracked)
pipeline-createdTypeGPU generated WGSL and the pipeline-creation call returned.pipeline, trigger, validation, resolveMs, createMs, wgsl
pipeline-creation-failedCreating a pipeline failed, so none exists.phase (resolve: TypeGPU, before WebGPU; create: WebGPU rejected it), errorType, message, wgsl
shader-diagnosticsThe compiler reported on a pipeline's shader.pipelineId, messages[] with lineNum and linePos in the generated WGSL
device-errorWebGPU reported an uncaptured error.errorType, message
device-lostThe device was lost or destroyed.reason, message
root-destroyedroot.destroy() was called.ownDevice, liveBuffers, liveTextures

With validation: 'deferred' (trigger lazy or initSync), pipeline-created only says that the call returned. An invalid shader still produces it; the problem arrives afterwards as shader-diagnostics or device-error. Only initAsync reports validation: 'passed'.

Snapshot

history() returns the most recent events, oldest first. getSnapshot() describes what is alive right now and can be cloned with structuredClone.

Console and JSON Lines#

consumers/ has small, dependency-free helpers that turn the stream into text. They only build strings; where the text goes is up to you. They are plain files, not part of the package: copy them into your project and change their type import from TypeGPU's source tree to typegpu/unstable-instrumentation.

  • attachConsoleReporter: one line per event, replaying history first. formatEvent and formatSnapshot in textReport.ts give you the same lines without a subscription.
  • createJsonlExport: one JSON object per line, each with a record field: header, event (exactly what was emitted) or snapshot.
  • parseJsonl: reads that text back and rejects a file or event whose schema version it does not know.

Cleanup#

root-destroyed counts the buffers and textures that were still alive at that moment (created, not destroyed, not yet garbage-collected). A non-zero count points at resources you never destroyed.

While disable()d, nothing is recorded, and a buffer created in that time stays untracked for good: bind-group entries that use it show resourceId: null.

Debugging a failed pipeline#

A compute pipeline calls a function that does not exist. Print the events with the console reporter, then read the WGSL TypeGPU generated from the failure the snapshot keeps.

Output in Chrome:

Line 1 is the browser's validation error, delivered as a device-error. Line 2 names the TypeGPU pipeline (broken), how it was created (initAsync) and that WebGPU rejected it (create). Line 3 is the compiler message, positioned in the generated WGSL: 1:51 is the call to definitelyUndeclared.

Reproduce it in Chrome with node real-gpu/run.mjs --example examples/broken-shader.ts. The repository's examples/ contain four more scenarios.
